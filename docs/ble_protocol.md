# 导航屏 BLE 通信协议 v1.0

手机（BLE Central / 客户端）→ 圆屏（BLE Peripheral / GATT Server / 服务端）。

> 为什么屏做服务端：Android 手机做 BLE 外设兼容性差，ESP32 做 GATT Server 是标准解法，
> 且屏一上电就在广播，手机随时能连上来。

---

## 一、GATT 定义

| 项目 | 值 |
|------|-----|
| 设备名 | `NavScreen` |
| 服务 UUID | `0000ff10-0000-1000-8000-00805f9b34fb` |
| 数据特征（手机→屏，Write / Write No Response） | `0000ff11-0000-1000-8000-00805f9b34fb` |
| 状态特征（屏→手机，Notify） | `0000ff12-0000-1000-8000-00805f9b34fb` |
| MTU | 建议 185（默认 23 也能跑，但长路名会拆包） |

**屏→手机的状态通知**（1 字节）：`0x00 空闲 / 0x01 已连接 / 0x02 收到帧 / 0xFF 校验错误`

---

## 二、帧格式

```
┌────────┬────────┬────────┬────────┬──────────────┬────────┐
│ 0xAA   │ 0x55   │ TYPE   │ LEN    │ PAYLOAD(LEN) │ CRC8   │
│ SOF    │ SOF    │ 1 byte │ 1 byte │ 变长         │ 1 byte │
└────────┴────────┴────────┴────────┴──────────────┴────────┘
```

- 所有多字节字段 **小端序**
- `CRC8` = 从 TYPE 到 PAYLOAD 结束所有字节求和后取低 8 位，再按位取反（`~sum & 0xFF`）
- 单帧最长 180 字节，超长的路名请截断到 40 字节以内

## 三、帧类型

### 0x01 NAV_STATE —— 导航状态（手机每 1 秒发一次，或状态变化时立即发）

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 1 | turn | 转向指令，见下表 |
| 1 | 2 | dist_m | 距下一个动作的米数（0~65535） |
| 3 | 4 | remain_m | 全程剩余米数 |
| 7 | 2 | remain_s | 全程剩余秒数 |
| 9 | 1 | speed_kmh | 当前车速 |
| 10 | 1 | name_len | 路名长度 n |
| 11 | n | road_name | 路名 UTF-8（如"东一路"） |

**turn 取值**

| 值 | 含义 | 值 | 含义 |
|----|------|----|------|
| 0 | 直行 | 6 | 靠左行驶 |
| 1 | 左转 | 7 | 靠右行驶 |
| 2 | 右转 | 8 | 到达目的地 |
| 3 | 稍向左 | 9 | 进入环岛 |
| 4 | 稍向右 | 10 | 驶出环岛 |
| 5 | 掉头 | 11 | 偏航，重新规划中 |

### 0x02 POSITION —— 位置（手机每 1 秒发一次；屏上有 GPS 时可不发）

| 偏移 | 长度 | 字段 |
|------|------|------|
| 0 | 8 | 纬度（double，GCJ-02） |
| 8 | 8 | 经度（double，GCJ-02） |
| 16 | 2 | 航向角（度 ×10，0~3599） |
| 18 | 1 | 速度 km/h |
| 19 | 1 | 定位有效标志（1=有效） |

### 0x03 TEXT —— 文本信息

| 偏移 | 长度 | 字段 |
|------|------|------|
| 0 | 1 | 子类型：0=目的地 1=提示 2=限速/电子眼 3=车道信息 |
| 1 | 1 | 文本长度 n |
| 2 | n | 文本 UTF-8 |

### 0x04 HEARTBEAT —— 心跳（手机每 5 秒发一次，屏端 10 秒收不到就认为断开）

| 偏移 | 长度 | 字段 |
|------|------|------|
| 0 | 1 | 电量百分比（手机电量，0~100） |

### 0x05 ROUTE —— 规划路线（算路成功后发一次，之后每 30 秒或重算后发一次）

| 偏移 | 长度 | 字段 |
|------|------|------|
| 0 | 1 | 分包序号 seq：0 = 第一包（屏端清空旧路线），1,2,3… 追加 |
| 1 | 1 | 本包点数 n（每点 16 字节，建议 n ≤ 10，单帧 162+4 字节） |
| 2 | 16×n | 点序列，每点 = 纬度(double) + 经度(double)，**GCJ-02** |

> 屏端缓存最多 160 点。手机端负责抽稀（约 50 米一点），一条 10 公里的路约 200 点，
> 分 20 包发完即可，无需每帧超限。

## 四、通信时序

```
手机                                        圆屏
 │  扫描 → 发现 "NavScreen"
 │──────────── 连接 + 请求 MTU 185 ──────────▶│
 │◀──────────── 状态通知 0x01 已连接 ──────────│
 │──────────── 0x03 TEXT 目的地 ─────────────▶│  （显示目的地）
 │──────────── 0x01 NAV_STATE ───────────────▶│  （每 1s）
 │──────────── 0x02 POSITION ────────────────▶│  （每 1s）
 │──────────── 0x04 HEARTBEAT ───────────────▶│  （每 5s）
 │◀──────────── 状态通知 0x02 收到帧 ──────────│
```

## 五、断连处理

- 手机断连 → 屏端 10 秒无心跳，界面顶部状态条显示"未连接"，继续用板载 GPS + 离线底图导航
- 手机重连 → 自动恢复推送，不需要重启固件
- 这一条很重要：**手机没电/没信号时，这台屏依然是一台能用的 GPS 导航仪**
